## 1. Action spotting (стиль SoccerNet) для одной метки на нарушение

**Каноническое название:** action spotting / precise event spotting; метрики tight/loose Average-mAP (a-mAP).

**Источники**
- SoccerNet-v2 (Deliège et al.), постановка задачи и метрика: https://arxiv.org/abs/2011.13367 [OK, только аннотация; определение допусков в аннотации нет].
- E2E-Spot, Hong et al., ECCV 2022: https://arxiv.org/abs/2207.10213, код https://github.com/jhong93/spot (BSD-3-Clause) [OK].
- Победитель SoccerNet-2022 (Yahoo Research), Soares & Shah: https://arxiv.org/abs/2206.07846 (разобран через https://ar5iv.labs.arxiv.org/html/2206.07846) [OK].
- Репозиторий соревнования, лидерборды tight/loose: https://github.com/SoccerNet/sn-spotting [OK, лицензия на странице не указана — смотреть файл LICENSE, [?]].

**Что реально делают победители (проверено)**
- Yahoo 2022: якоря каждые 0.5 с (признаки ресемплируются с 1 до 2 в секунду), у каждого якоря уверенность и смещение по времени ("displacement"); 1D U-Net ~23M параметров; поздняя фузия логитов двух типов признаков; Soft-NMS в 1D: уверенность умножается на min{|s−t|/(w/2), 1}. Окна, подобранные под tight a-mAP: NMS 3 с, Soft-NMS 8 с (против ~20 с в прежних работах под обычную a-mAP). SAM и mixup (только для модели уверенности). Прирост от Soft-NMS + фузии: 62.6 -> 65.1 tight (Test).
- Tight a-mAP: радиус допуска = половина окна δ, шаг полсекунды [OK, из ar5iv Yahoo]. Точные значения tight/loose (1 с и 5 с) я не открывал — [?].
- E2E-Spot: покадровая кросс-энтропия, веса переднего плана 5x относительно фона (события < 3% кадров); dilation метки на ±1 кадр при обучении; NMS окно ±1 кадр (±2 при 2 fps); обучается на одной GPU, ~0.3 мс/кадр для лёгкой версии (RegNetY 200MF). Малый датасет: Figure Skating — 11 видео, 3674 события — качество в пределах 0.1–2.5 mAP от поз-признаков [OK].

**Про "гауссову мягкую метку":** в открытых мной работах (E2E-Spot, Yahoo) гаусса нет: там расширение метки на соседние кадры (E2E-Spot) и якоря со смещением (Yahoo). Конкретный гаусс в топ-решениях SoccerNet я не подтвердил — [?]. Идея разумная как самостоятельный приём, но ссылаться на него как на "приём победителей" нельзя.

**Рецепт для нас**
- Не обучать end-to-end на ~40 видеороликах. Взять замороженные признаки (DINOv2 по кропам зон, 2 кадра/с) плюс наши правила; обучать лёгкий 1D-head (небольшая TCN/GRU) или просто калибровать скоры правил.
- Целевое окно: ±1–2 с вокруг метки (мягкая цель, например гаусс sigma ~1 с или dilation ±1 шаг сетки 0.5 с — наш выбор, не из статей).
- Постобработка: пики -> Soft-NMS окно ~ 8 с (в видео 10–145 с с 1 нарушением можно просто argmax + 2-й пик, если он выше порога).
- Локальная метрика: доля нарушений с |t_pred − t_gt| <= tol, tol в {1, 2, 5} с + ложные срабатывания на чистых видео.
- Грубо->точно (идея 3): корректна, это обычная схема "2 fps -> refine" — [?] как именованный приём.

**Подводные камни:** при 1 событии на видео mAP по классам вырождается — считать recall@tol и FPR; метка организаторов "когда должно было случиться парное действие" не совпадает с визуальным пиком — нужен сдвиг, подбираемый на dev.

**Требования:** E2E-Spot BSD-3 (код); веса RegNetY из torchvision/timm — лицензию весов проверять отдельно [?]. Всё локально, лица не нужны. Скорость: 0.3 мс/кадр заявлена (на A5000), на CPU не измерено [?].

**Вердикт: USE WITH CARE** — использовать формат (мягкая цель, пики + NMS, метрика с допуском), но не полноценную обучаемую сеть spotting на 40 роликах.

## 2. Оставленные предметы: двойная фоновая модель

**Каноническое название:** abandoned object detection / temporarily static region detection; dual (long/short-term) background models.

**Источники**
- Porikli, "Detection of Temporarily Static Regions by Processing Video at Different Frame Rates", AVSS 2007, pp. 236–241 (MERL TR2007-040): https://www.merl.com/publications/TR2007-040 [OK]. Суть: два фона (короткий и длинный), смесь гауссиан, байесовское обновление с разными скоростями обучения, карта правдоподобия делит пиксели на движущиеся / временно статичные / фон; без трекинга.
- Журнальная версия EURASIP 2008: https://asp-eurasipjournals.springeropen.com/articles/10.1155/2008/197875 [найдено в поиске, не открывал полностью].
- Известная слабость: статичный объект постепенно "впитывается" в длинный фон; лечится селективным обновлением длинного фона (по результатам поиска, см. выше; первоисточник этого утверждения не открыт) [?].
- OpenCV: BackgroundSubtractorMOG2 / KNN. Значения по умолчанию из background_segm.hpp (OpenCV, Apache-2.0) [OK]: MOG2 history=500, varThreshold=16, detectShadows=true; KNN history=500, dist2Threshold=400, detectShadows=true; learningRate=-1 -> авто, 0 -> модель не обновляется, 1 -> полная переинициализация.

**Рецепт (ключевая модификация под нас)**
- Не нужны два MOG2: проще "заморозить" длинный фон — взять медианный кадр первых N секунд ролика (самоэталон, идея 6), learningRate=0, и сравнивать с коротким фоном (MOG2 history ~ 100–300 кадров при 5–10 fps или apply с learningRate ~0.005–0.01).
- Оставленный объект = пиксели, отличные от длинного фона, но совпадающие с коротким (то есть стали статичными) в зоне стола, и persist >= T секунд после того, как в зоне нет людей.
- Работать на сниженном fps (5–10) и уменьшенном кадре; считать только в ROI стола.
- detectShadows: теневые пиксели (значение 127) отбрасывать; для нашей цели лучше отключить или бинаризовать по 255.

**Подводные камни:** человек, стоящий неподвижно (кассир за столом), становится "оставленным" — гейтить по детектору людей (локальный YOLO/RT-DETR: проверять лицензию, Ultralytics YOLO — AGPL-3.0 -> избегать, [?] подтвердить; RT-DETR/YOLOX/D-FINE обычно Apache-2.0, [?]); смена освещения и автоэкспозиция камеры -> нормализовать яркость кадра/использовать градиентные признаки; сам стол и бумаги, которые кассир кладёт штатно -> различать по контексту "ушёл ли кассир".

**Требования:** OpenCV Apache-2.0 [OK], локально, CPU быстро, лица не нужны.

**Вердикт: USE** (в упрощённом виде: замороженный начальный фон + короткий MOG2/KNN + гейт по людям).

## 3. Change-point detection по рядам признаков зон

**Каноническое название:** offline change point detection; PELT (Pruned Exact Linear Time).

**Источники**
- Killick, Fearnhead, Eckley, JASA 107(500):1590–1598, 2012: https://arxiv.org/abs/1101.1438 [найдено в поиске, аннотация подтверждена].
- Truong, Oudre, Vayatis, "Selective review of offline change point detection methods", Signal Processing 167:107299, 2020: https://arxiv.org/abs/1801.00718 [найдено в поиске]. Описание: метод = функция стоимости + метод поиска + ограничение на число точек.
- Библиотека ruptures: https://github.com/deepcharles/ruptures — лицензия BSD-2-Clause (Copyright ENS Paris-Saclay, CNRS), "Maintained: yes", 2.1k звёзд [OK].

**Рецепт**
- Ряд: 1–2 Гц, 1–5 признаков на зону (доля изменённых пикселей относительно эталона, DINOv2-расстояние до эталона, состояние двери/экрана).
- `rpt.Pelt(model="l2", min_size=3, jump=1).fit(x).predict(pen=...)`; pen подбирать по чистым видео (см. п. 6) так, чтобы на них точек смены почти не было. (Имена параметров pen/min_size/jump подтверждены только по заголовку документации, сама страница не открывалась полностью [?].)
- Для малых рядов (20–300 точек) PELT работает мгновенно; можно и Binseg/Window.

**"Смена без возврата":** после ряда сегментации сравнить среднее последнего сегмента с средним первого (эталона): |mu_last − mu_0| > порог и длительность последнего сегмента >= T = нарушение; если mu_last ≈ mu_0 — вернулось, это норма. Это по сути проверка "первый сегмент ≈ последний", специализированного названия я не нашёл — [?].

**Подводные камни:** PELT чувствителен к pen и к автокоррелированному шуму; позы людей создают огромные временные всплески (нужно маскировать кадры с людьми в зоне или медианно сглаживать); для тестового видео с нового ракурса абсолютные значения не переносятся — нормировать по первым секундам ролика.

**Требования:** BSD-2 [OK], чистый Python/NumPy, CPU, лица не нужны.

**Вердикт: USE** (но как вспомогательный слой над готовыми признаками; можно заменить простым правилом "начало vs конец").

## 4. Парные события / "невозврат": есть ли устоявшееся имя

**Что подтверждено**
- Event Calculus для распознавания активности в видео: Artikis et al., "A Logic Programming Approach to Activity Recognition": https://arxiv.org/abs/0905.4614 [найдено в поиске, не открывал]; вероятностное расширение: https://arxiv.org/abs/1207.3270 [найдено в поиске]. Ключевое понятие Event Calculus — fluent (состояние, сохраняющееся по инерции, пока не будет "прервано" событием) — ровно наша модель "дверь открыта, пока не закрыта".
- VERSA (O'Hara): декларативные пространственно-временные шаблоны событий, мониторы поверх выходов трекера: https://arxiv.org/abs/1007.3772 [OK].
- Интервальная логика Аллена и онтологии событий (VERL/VEML, Nevatia) — по пересказу поиска, первоисточники не открывались [?].
- Metric temporal logic / runtime verification в видео: поиск прямого применения не дал [?]. Идея "ограниченного отклика" (bounded response: после A должно быть B в течение T) — общее понятие из temporal logic, но как цитируемую работу для видео я её не нашёл.

**Как формулировать в защите:** "рассуждение о состояниях (fluents) по Event Calculus: initiates(открыл дверь) / terminates(закрыл дверь); нарушение, если fluent holds_at конца эпизода или превышает допустимый срок". Реализовать самим конечным автоматом на 20 строк — внешний reasoner (Prolog/RTEC) не нужен.

**Подводные камни:** ошибки датчика размножаются; делать вероятностное состояние (скор в [0,1]) и порог из п. 6; на ролике 10–145 с граница "ролик закончился" — отдельная семантика ("не вернулось к концу").

**Требования:** сам FSM — свой код, лицензии не нужны; Event Calculus/VERSA — только как цитата. Реализации (RTEC и др.) я не проверял на лицензию [?].

**Вердикт: USE** как концепция и терминология (fluent / Event Calculus), реализацию писать самим; сторонние фреймворки SKIP.

## 5. Гомография по плоскому объекту, bird's-eye view

**Каноническое название:** planar homography / inverse perspective mapping (IPM), rectification, ground-plane homography.

**Источники**
- Обзор IPM, ограничения: https://developer.ridgerun.com/wiki/index.php/Birds_Eye_View/Concepts/How_BEV_Works [найдено в поиске, не открывал]; подход без ручной калибровки (точка схода + горизонт -> H): ICCVW 2019, Abbas & Zisserman, https://openaccess.thecvf.com/content_ICCVW_2019/papers/GMDL/Abbas_A_Geometric_Approach_to_Obtain_a_Birds_Eye_View_From_ICCVW_2019_paper.pdf [найдено в поиске; авторов в выдаче не было — фамилия "Abbas" из имени файла, второго автора не подтверждаю].
- OpenCV findHomography / warpPerspective — туториал https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html (403 на момент попытки [?]); сама библиотека Apache-2.0 [OK].

**Рецепт**
- 4 угла столешницы (ручная разметка один раз на камеру или детектор углов) -> H в прямоугольник известного соотношения сторон -> зоны и правила задаются в координатах стола. Для нового ракурса финального видео нужна 4-точечная разметка либо автоматический поиск (SIFT к эталону + RANSAC, `cv2.findHomography(..., cv2.RANSAC, 3.0)`).
- Для людей проецировать только точку ног (нижняя середина рамки) — вертикальные объекты в BEV растягиваются, это явно указано в источнике по IPM.

**Подводные камни:** гомография точна лишь для точек на этой плоскости (столешница); предметы на столе — на высоте, смещение параллаксом; верхняя плоскость стола и пол — разные плоскости, нужны разные H; кадр 464x848 даёт низкое разрешение после ректификации далёких зон; при ошибке в 4 углах на 5 px ошибка в BEV может быть заметной; экстремальный угол обзора ухудшает устойчивость.

**Требования:** Apache-2.0, локально, CPU, лица не нужны.

**Вердикт: USE WITH CARE** — как запасной канал и для правил "сторона кассира/клиента"; основной путь — признаки, инвариантные к ракурсу (локальные патчи), плюс ручная разметка 4 точек как честный fallback.

## 6. Чистые ролики как нулевое распределение, пороги с контролем FPR

**Каноническое название:** conformal anomaly detection / conformal outlier detection (conformal p-values); inductive (split) conformal.

**Источники**
- Bates, Candès, Lei, Romano, Sesia, "Testing for Outliers with Conformal p-values", Annals of Statistics 51(1):149–178, 2023: https://arxiv.org/abs/2104.08279 [найдено в поиске, аннотация подтверждена]. Даёт конформные p-значения для проверки, что новая выборка из того же распределения, что и калибровочная; границы на FPR как функцию порога.
- Laxhammar & Falkman — conformal anomaly detection (CAD/ICAD) для траекторий в наблюдении: упоминание и год 2010 из поиска; первоисточники не открывал, годы ICAD расходятся (2010/2015) — не цитировать год без проверки [?].

**Минимальный рецепт**
1. Для каждого правила r определить скор s_r(видео) = максимум скора правила (нарушенность) по ролику.
2. Калибровочное множество = чистые dev-ролики (n шт.); s_1..s_n.
3. Для нового ролика: p = (1 + #{i: s_i >= s_new}) / (n + 1). Порог "тревога", если p <= alpha. Гарантия: P(ложная тревога на чистом) <= alpha при обмениваемости.
4. С n = 10–15 чистых роликов минимально достижимое p = 1/(n+1) ~ 0.07–0.09, то есть alpha < 0.07 недостижим. Это надо проговорить в защите.
5. Не использовать одни и те же чистые ролики и для настройки признаков, и для калибровки (иначе оптимистично): держать часть отдельно либо leave-one-video-out.

**Подводные камни:** обмениваемость нарушается при сдвиге ракурса/света (финальное видео с нового угла!) — калибровать скор на самонормализованных признаках (идея 16) и держать консервативный запас; много правил -> поправка на множественность (Bonferroni или BH — Bates et al. обсуждают FDR); "парные" чистые двойники берутся из того же ракурса, что и нарушение — это смещает порог, но не в опасную сторону.

**Требования:** метод — статистический, внешних моделей нет; для реализации достаточно NumPy (готовые пакеты conformal не нужны). Локально, быстро, лица не нужны.

**Вердикт: USE** (как "порог = квантиль нулевого распределения" с честным p-значением).
