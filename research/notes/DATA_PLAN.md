# План работы с данными: разметка состояний + синтетика

Цель — перейти от «42 ролика с одной меткой» к тысячам размеченных кадров, на которых учатся «датчики состояния». Нарушение потом собирается правилами из состояний.

## 1. Разметка состояний (интервалами, а не каждый кадр)

Кадров при 2 fps ≈ 2 900 (суммарно ~24 минуты видео). Размечать каждый кадр вручную долго, поэтому размечаем **интервалы**: «с 4.5 по 9.0 с дверь открыта». На ролик обычно 3–8 интервалов; кадры получают метки автоматически из интервалов.

### Атрибуты (схема `states.csv`: video, attr, value, t_start, t_end)
| Атрибут | Значения | Зачем (типы нарушений) |
|---|---|---|
| `door` | closed / open | дверь не закрыта; вход посторонних |
| `cashier_present` | at_desk / in_room / absent | уход с рабочего места — триггер проверок |
| `outsider_zone` | none / client_side / cashier_side | посторонний у места кассира |
| `laptop_screen` | unlocked / locked / off / not_visible | компьютер не заблокирован |
| `desk_items` | набор: cash, bag_money, documents, phone, bag_personal, cup_food, none | ценности/личные вещи/еда на столе |
| `in_hands` | phone / cash / cup_food / none | телефон, еда, ручной пересчёт |
| `safe` | closed / open / not_visible | сейф открыт |
| `handover` | none / hand_to_hand / via_desk | передача ценностей |
| `camera_view` | A / B / C / D | ракурс (для валидации устойчивости) |

### Порядок работы
1. **Предразметка автоматически**: смена ракурса, появление/исчезновение людей и движение в зоне двери — по разнице кадров. Даёт черновые границы интервалов.
2. **Ручная правка** по листам кадров 2 fps: оператор правит границы и значения. Оценка: 5–10 минут на ролик → 4–7 часов на 42 ролика; делится между участниками.
3. **Контроль качества**: 10 % роликов размечают двое, считаем согласие по атрибутам.
4. **Связка с разметкой организаторов**: в каждом ролике с нарушением таймкод должен попадать на смену состояния, которая объясняет тип (например, `cashier_present: at_desk→absent` при `laptop_screen=unlocked`). Если не попадает — тип выбран неверно.

### Что получаем
- Обучающие пары «кадр/кроп → состояние» для небольших классификаторов (дверь, экран, предметы на столе, что в руках).
- Таблицу событий для правил и для таймкода.
- Набор для валидации, разбитый по ракурсу (`camera_view`): учим на одних ракурсах, проверяем на другом — имитация финального видео «под другим углом».

## 2. Синтетика и аугментации

| Приём | Что делаем | Какую проблему закрывает |
|---|---|---|
| Геометрия ракурса | перспектива, поворот ±15°, масштаб, сдвиг, кроп, отражение | новый ракурс в финале (10 баллов) |
| Фотометрия | яркость, контраст, баланс белого, шум, размытие, JPEG-сжатие | другая камера и свет |
| Вклейка объектов (copy-paste) | телефон, стакан, сумка, пачка денег на стол или в руку — из вырезок наших же кадров и открытых изображений с подходящей лицензией | мало примеров редких типов (1–3 ролика на тип) |
| Удаление объектов | закрашивать предмет на столе (inpainting) → «чистый» вариант того же кадра | пары «нарушение / норма» на одной сцене |
| Подмена экрана | вклеить в экран ноутбука «рабочую таблицу» или «экран блокировки» | один пример незаблокированного ПК |
| Временная синтетика | склейка фрагментов (уход кассира + последующие кадры со столом), ускорение/замедление | новые сочетания событий |

Ограничения: синтетику используем для обучения датчиков, а валидируем только на реальных кадрах (и на своих съёмках, если будут). Источники вклеиваемых объектов — только с лицензией, разрешающей коммерческое использование.

## 3. Группы для валидации
- Дубликаты в одной группе: Х-4 = Х-47, Х-5 = Х-48.
- Разбиение по ракурсу камеры (leave-one-view-out) — главная проверка устойчивости.
- Ролик Х-12 (ракурс меняется на ~35 с) — отдельный тест.

## 4. Открытые вопросы
- Спорные нарушения (13, 22, 17, 47, частично 1): оставить как «нарушение порядка кассовой операции» с осторожной формулировкой или уточнить у организаторов.
- Нужна ли своя съёмка (если найдётся помещение с дверью и столом) — даёт новые ракурсы надёжнее синтетики.
