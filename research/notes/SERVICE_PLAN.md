# План сервиса: бэкенд и фронтенд

Статус: план согласован, реализация — после фиксации модели. VPS / публичный URL — отдельное обсуждение.
Главное: жюри проверяет **только через API и автоматически** → точное соответствие схеме ТЗ (разд. 10) и надёжность важнее всего.

## Бэкенд — FastAPI + Uvicorn (MIT/BSD)
```
POST /api/v1/analyze     multipart, поле file (.mov) → 202 {"job_id": "..."}
GET  /api/v1/jobs/{id}   → {job_id, status: processing|done|failed, verdict, violations[]}
GET  /health             → проверка живости
/ , /ui/*                → страница интерфейса и её маршруты (без ключа)
```
- Pydantic-модели строго по схеме ТЗ: `verdict` ∈ {violation, no_violation}; `violations` пустой при отсутствии; поля `type`, `timecode_sec`, `description`, `evidence_frames[{timestamp_sec, image_base64}]` (1–3 JPEG).
- Норма и источник — внутри `description` (в схеме нет отдельного поля); доп. поля (`rule`, `type_code`) — опционально, не вместо основных.

## Ловушки и решения
| # | Ловушка | Решение |
|---|---|---|
| 1 | **5 видео сразу → очередь → 5-е не успеет за 5 мин** | несколько рабочих процессов (ProcessPool, потоки torch поделены) + бюджет времени внутри обработки (fps подбирается под длину видео, цель ≤ 3.5 мин); нагрузочный тест |
| 2 | POST ждёт обработки → таймаут | POST только сохраняет файл потоком на диск и ставит в очередь, сразу отдаёт job_id |
| 3 | API-ключ | заголовок `X-API-Key`, `secrets.compare_digest`, без/неверный → 401; ключ из переменной окружения |
| 4 | Ключ утечёт в браузер | UI ходит через `/ui/*` без ключа (FAQ 27: авторизация для UI не нужна) |
| 5 | Перезапуск теряет задачи | статусы и результаты в SQLite |
| 6 | Неверные статусы | внутренний `queued` наружу = `processing`; любое исключение → `failed` с причиной, не 500 |
| 7 | Хранение тестовых видео (R21) | удалять видео после обработки, хранить только JSON |
| 8 | Тяжёлый ответ | кадры-доказательства ~640 px, JPEG q≈80 |
| 9 | Локальность и переносимость (R13) | веса в Docker-образе, `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1` |
| 10 | Прокси режет загрузку | Caddy/Nginx: HTTPS, лимит тела ~100 МБ (у Nginx по умолчанию 1 МБ), увеличенные таймауты |

## Контрактный тест (прогонять перед каждой отправкой)
- повтор действий жюри: `curl POST` → опрос `GET` → проверка JSON по JSON Schema;
- без ключа / неверный ключ → 401;
- не .mov / битый файл → `failed` с причиной;
- 5 параллельных загрузок самых длинных роликов → все `done` < 5 мин;
- работа с отключённым интернетом.

## Фронтенд — одна простая страница
1. Загрузка видео с прогрессом.
2. Статус обработки (опрос раз в 2 с).
3. Крупный вердикт: «Нарушение не обнаружено» / «Обнаружены признаки возможных нарушений».
4. Карточка на каждое нарушение: тип, таймкод, кадр-доказательство с увеличенной вставкой, что видно, норма (документ, пункт).
5. Видеоплеер с отметками событий на таймлайне; клик по таймкоду перематывает.
6. Дисклеймер: «результат — подсказка для проверки человеком» (R17).
Технология — на выбор команды: HTML+JS или React/Vite. Без логина, истории, экспорта (FAQ 27). Язык — русский.

## Разделение работы
- **Claude**: контракт API (Pydantic-схемы), каркас FastAPI с очередью, ключом и SQLite, адаптер «пайплайн → JSON», контрактный и нагрузочный тесты.
- **Команда**: UI поверх `/ui/*`, по желанию — доработка бэкенда.
- **Отдельно**: VPS (CPU или GPU), публичный URL, Docker, прокси.
