# Видеоконтроль · Контроль кассовых операций

AI-сервис для ForteBank (Datathon '26): по видеозаписи работы кассира находит визуальные признаки возможных нарушений кассовой дисциплины, показывает таймкод, кадры-доказательства, понятное объяснение и пункт нормативного акта РК. Результат — подсказка для проверки человеком, а не юридическое заключение.

## Адреса для жюри
| | |
|---|---|
| Веб-интерфейс | адрес передан в форме сдачи (после запуска — `tools/PUBLIC_URL.txt`) |
| API (base URL) | тот же адрес + `/api/v1` |
| API-ключ | передан в форме сдачи; заголовок `X-API-Key` |

Сервис доступен 18.10 с 12:00 до 14:30. Если адрес изменится (перезапуск туннеля), новый будет сообщён организаторам.

Актуальная проверка по ТЗ: [docs/tz-audit.md](docs/tz-audit.md). Адрес сверяйте с `tools/PUBLIC_URL.txt`: после перезапуска туннеля он меняется.

## Коротко о решении
- **Нейросеть одна** — детектор D-FINE-S (Apache-2.0, 41 МБ): видит людей и предметы.
- **Что считать нарушением, решают 5 датчиков состояний**, которые считают всё относительно людей и предметов в кадре, а не координат конкретной комнаты. Решению не нужны эталоны и зоны помещения; при сильной смене ракурса качество снижается (замер в docs/architecture.md).
- Если датчики ничего конкретного не нашли, но в кадре достаточно долго присутствовали несколько людей, видео помечается «требуется проверка». Это эвристика, а не подтверждение работы с ценностями; она даёт много ложных тревог (см. ограничения).
- Нормы не генерируются моделью: типы связаны со справочником актов РК. Для косвенных связей и непроверяемых обстоятельств указаны ограничения.
- Полностью локально, CPU, без облачных ИИ, без распознавания лиц и звука.

## Быстрый запуск
1. Окружение и зависимости — по [docs/usage.md](docs/usage.md#запуск-сервиса); один раз собрать модель: `python solution/export_onnx.py`.
2. В `service/.env` задать `SERVICE_API_KEY` (шаблон — `service/.env.example`).
3. Двойной клик по `START_SERVICE.bat`: откроются окна «сервис» и «туннель», публичный адрес появится в окне и в `tools/PUBLIC_URL.txt`.

Проверка: `<адрес>/health` → `"ready_workers":5`; `<адрес>/api/v1` — справка по API. Памятка на случай сбоев — [tools/RUNBOOK.md](tools/RUNBOOK.md).

## Структура
```
dataton/
├── START_SERVICE.bat         запуск двойным кликом: сервис + публичный туннель
├── RESTART_SERVICE_ONLY.bat  перезапуск только сервиса (публичный адрес не меняется)
├── service/            сервис: FastAPI, очередь на 5 ML-процессов, веб-интерфейс static/, тесты, Docker
├── solution/           ML-ядро
│   ├── inference.py        вход для сервиса: Analyzer().run(видео) → JSON
│   ├── pipeline.py         кадры → детектор D-FINE (ONNX) → датчики → ответ с нормами
│   ├── sensors_core.py     ядро: трек кассира, 5 датчиков, открытый класс
│   ├── sensors/            датчики: дверь, экран, посторонний, ценности, личные вещи
│   ├── rules.json          справочник типов: нормы РК и объяснения
│   ├── assets/             views.json; эталонные кадры (только режим h5) и ONNX-модель — не в git
│   ├── bench.py, evaluate.py   стенд и оценщик по критериям жюри
│   ├── experiments/        отклонённые эксперименты (VLM, поза, модель визита…)
│   └── runs/               скрипты и результаты проверок (регрессии, тест ракурса, настройка порогов)
├── docs/               документы к сдаче (ТЗ, раздел 8)
├── pitch/              презентация
├── tools/              запуск на ноутбуке, памятка RUNBOOK.md
├── research/           исследования: заметки и журнал экспериментов (notes/), ядра Kaggle (kaggle/), условие кейса (case/)
└── artifacts/          логи и отчёты проверок сервиса, скриншоты UI (не в git)
```
Журнал всех экспериментов: [research/notes/experiments.md](research/notes/experiments.md).
