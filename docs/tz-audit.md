# Проверка проекта по ТЗ организаторов

Дата: 18.10.2026. Источник: `research/case/Кейс_ForteBank.docx`, включая FAQ. Проверяется текущий сервис на Windows, а не только описания в презентации. Презентация не изменялась.

## Исправлено

1. Docker-контекст исключал `solution/sensors/`. Ошибки импорта датчиков при этом подавлялись, что могло дать неполный или ложный чистый результат. Датчики включены в образ; ошибка датчика теперь завершает задачу как `failed`. Сборка проверяет импорт всех датчиков.
2. Ответ обрезался до трёх типов событий. В ТЗ ограничены 1–3 **кадра на событие**, а не число событий. Все обнаруженные разные типы теперь попадают в ответ.
3. Основной режим `sensors` при старте загружал частные эталонные фотографии, хотя не использовал их. Зависимость убрана; режим `h5` по-прежнему требует свои исследовательские assets. Частные JPG исключены из Git и Docker.
4. Экспорт ONNX не создавал выходной каталог. Каталог теперь создаётся; добавлена зависимость `onnx` для экспорта. Docker экспортирует модель при сборке и проверяет запуск именно ONNX Runtime, чтобы не переходить незаметно на медленный PyTorch.
5. Инструкция запуска создавала другое окружение, чем использовал `tools/serve.py`. Инструкция приведена к `service/.venv`; добавлены подготовка весов и экспорт ONNX.
6. Заголовок события о ПК утверждал отсутствие блокировки, хотя датчик видел только яркость экрана. Заголовок и объяснение теперь описывают предположение. Уточнено условие более 30 минут неактивности в № 53 п.71 пп.9; короткий уход не доказывает нарушение этой нормы.
7. Уточнены косвенная связь открытой двери с нормой об устройстве помещения, исключение для операций приёма/выдачи клиенту в № 231 п.42 и пределы общего типа `procedure`. Присутствие двух людей больше не описывается как доказанная операция с наличными.
8. Для № 81 найден официальный код `V2600038505`; событие о доступе человека теперь ссылается на соответствующий акт. Старые отчёты о неудачной приёмке обозначены как исторические; текущие результаты приведены ниже.
9. Восстановлен публичный туннель, актуальный адрес сохраняется в `tools/PUBLIC_URL.txt`. После любого перезапуска туннеля адрес надо сверять с адресом, переданным жюри.

## Проверки

- `service/.venv/Scripts/python.exe -m pytest service/tests -q`: 27 тестов прошли, включая три новых регрессии (ошибка датчика, более трёх типов, запуск без частных эталонов).
- Python-синтаксис основных модулей, JSON справочника и JavaScript-синтаксис проверены.
- Браузерная проверка: реальная загрузка синтетического видео, результат `no_violation`, повторное открытие результата, помощь, отсутствие горизонтального переполнения на ширине 390 px, отсутствие ошибок JavaScript. Отчёт: `artifacts/tz-audit/ui-report.json`.
- Проверка через публичный туннель с настоящим роликом была отклонена автоматической проверкой разрешений: передача ограниченных данных внешнему посреднику без отдельного согласия. Используется безопасная замена: реальные ролики только на localhost, публичный API — на синтетическом видео без данных кейса. Эти две проверки не доказывают скорость передачи настоящего 29-МБ файла по каналу жюри.

## Ограничения качества

Старые замеры качества из `docs/limitations.md` не пересчитывались в этом аудите: на 7 отложенных видео заявлены 3/3 найденных нарушений, 3/4 ложных тревог, верный тип 1/3 и таймкод в пределах ±2 секунд 0/3. Они показывают существенный риск по критериям качества, классификации, локализации и нового ракурса. Пороги и веса модели в этом аудите не изменялись. Нельзя обещать отсутствие пропусков или готовность к эксплуатации в банке.

Сравнение 0.69/0.69/0.69 в архитектуре проверяет отключение знаний о комнате, а не независимую съёмку с новой камеры. Итоговые баллы жюри этим не подтверждаются.

Во время длинного нагрузочного теста дополнительная проверка повреждённого файла через публичный адрес превысила собственный 30-секундный лимит теста, ожидая свободный обработчик. Этот дополнительный прогон остановлен. После освобождения очереди публичная проверка успешно повторена. Пять одновременно выполняемых длинных задач заняли все пять обработчиков; задержка дополнительных запросов остаётся свойством очереди. ТЗ не устанавливает отдельный 30-секундный лимит для повреждённых файлов.

Запас локального прогона до 300 с — около 95 с. Он не гарантирует выполнение через медленный внешний канал. Для настоящего 29-МБ файла время загрузки по внешней сети в текущем аудите не измерялось.

Текущий публичный адрес записан в README и `tools/PUBLIC_URL.txt`; API — тот же адрес с `/api/v1`. Переданная ранее ссылка сама не обновляется. Отправку нового адреса и ключа организаторам аудит не выполняет.

Штатный скрипт `run_service.ps1` приведён к окружению `service/.venv`, как инструкция установки. Скрипты туннеля и общего запуска рассчитаны на порт 8765: при переносе с другим `SERVICE_PORT` нужно согласовать порт в этих скриптах. Текущий проверенный запуск использует 8765.
