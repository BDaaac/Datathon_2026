# Обновление ML для сервиса (от ML-части)

**Интерфейс не изменился:** `Analyzer().run(path)` → `verdict`, `violations[...]`, `processing_sec`.

## Что поменялось внутри
- `Analyzer.run` теперь запускает **текущую лучшую логику** (гибрид H1: правила A8 + выбор главного события по надёжности + проверка геометрии), а не v0. Раньше сервис отдавал v0 — это было расхождение с экспериментами, исправлено.
- Новые модули в `solution/`: `features.py` (признаки двери/стола/экрана из кадра) и `decide.py` (правила). `pipeline.analyze` вызывает их; дополнительных весов и моделей **нет** — по-прежнему только D-FINE-S (та же ревизия). `prepare_weights.py` менять не нужно.
- В `violations` могут быть **несколько событий**; первое — главное (самое надёжное). В `description` уже есть норма и ссылка на adilet (из `solution/rules.json`, поле `urls`).
- Если геометрия ракурса ненадёжна (новый угол камеры), сервис по умолчанию выдаёт `violation` с общим типом «Нарушение порядка приёма/выдачи ценностей» — это осознанная политика (пропуск дороже ложной тревоги).

## Скорость (открытая задача ML)
- Узкое место — детектор D-FINE на CPU (~0.5 с/кадр при 2 fps). Новые признаки добавляют несколько мс на кадр.
- В работе у ML: адаптивная частота кадров и/или OpenVINO, чтобы 5 параллельных видео укладывались в 300 с. Сообщим отдельно.

- **Адаптивная частота кадров**: видео длиннее 60 с обрабатываются на 1 кадр/с (короче — 2 кадра/с). Качество на наших роликах не изменилось.
- Замер локально (Intel Core Ultra 5, свободный CPU): **Х‑14 (143 с видео) — 62 с** на одно видео (было 184–302 с).
- Просьба: пересобрать образ и прогнать **5 параллельных Х‑14** в контрактном тесте; сообщить время в `NEEDS_FROM_ML.md`.
- Логика вердикта: **гибрид H2** (правила A8 + главное событие по надёжности + поправки таймкода + запасной вердикт с общим типом). Выбран по стресс-тесту нового ракурса. Включается в `solution/decide.py` (`BEST`); интерфейс прежний.
